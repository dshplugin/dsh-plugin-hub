DSH Plugin Hub is the community plugin marketplace for DeepSeek Harness. This release separates "a broken package in your local profile" from "a plugin's own problem", and reworks the version dialog. Website: <https://dsh-plugin.org>

## What changed

- **The marketplace no longer fails with a catalog load error when the local curl cannot decode the negotiated encoding.** The catalog fetch asks for gzip explicitly instead of letting curl negotiate, and falls back to HTTP/1.1 once if the first attempt fails. A failure now also returns the concrete reason (exit code and the last error line) instead of a bare message.
- **Install failures are no longer blamed on the wrong plugin author.** pnpm re-validates the whole profile on every install, so a broken local (file: / link:) dependency that already exists in the profile used to fail whichever plugin the user installed and file the report against its author. That case is now recognized as local profile state: the dialog names the offending local dependency and says how to handle it, with no issue entry pointed at the plugin author.
- **The failure reason no longer assumes a "native module".** A blocked build script is not necessarily native, so the wording now says that a package in the plugin install tree declares a build script that pnpm blocks, and that pnpm fails the whole install until it is approved.
- **The version dialog shows the version once.** The version number is the single primary element, followed by a status chip (up to date / update available / held for the 24-hour window) and the publish time. The changelog no longer repeats the version in its own title, and the action is a single Close button.
- Thanks to @dingminhua for the detailed analysis of the misattributed build failure, and to @WEGFan for the on-site screenshots.

## Install

```bash
dsh plugin --profile web add dsh-plugin
dsh plugin --profile web add git+https://github.com/dshplugin/dsh-plugin-hub.git
```
