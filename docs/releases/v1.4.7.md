**v1.4.7 — curl keeps working when Windows blocks its certificate revocation check**

DSH Plugin Hub is the community plugin marketplace for DeepSeek Harness. This release hardens the connectivity layer: on Windows, curl could refuse to connect at all because Schannel insists on fetching certificate revocation information before it will finish a TLS handshake — and the marketplace looked broken even though npm, git and the browser worked fine.

**Website**: [dsh-plugin.org](https://dsh-plugin.org)

**What's New**

- **A blocked revocation check no longer costs you the marketplace** — On Windows, curl now runs with `--ssl-revoke-best-effort`, so a handshake that cannot reach the CRL/OCSP service degrades to a best-effort check instead of failing outright. Builds of curl older than 7.70, which do not know the option, are detected and retried without it, so they keep working exactly as before.
- **Diagnostics name the real cause instead of "Unreachable"** — When a channel fails because the certificate revocation check is blocked, the diagnostics row now reads "Cert check blocked" and explains that this is a local TLS issue rather than a network outage. The proxy check in Settings makes the same distinction, so it no longer suggests a perfectly good proxy address is wrong.
- **The plugin list falls back to the local cache** — If the live catalog fetch fails, the last successfully fetched catalog is served instead of an error, so the marketplace no longer goes empty because of one failed request.

**Installation**

Option 1 · via npm (recommended):

```bash
dsh plugin --profile web add dsh-plugin
```

Option 2 · via the official GitHub repository:

```bash
dsh plugin --profile web add git+https://github.com/dshplugin/dsh-plugin-hub.git
```
